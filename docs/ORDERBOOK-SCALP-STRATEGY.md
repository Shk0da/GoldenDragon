# OrderBook Scalping Strategy - Инструкция по запуску

## ⚠️ ПРЕДУПРЕЖДЕНИЕ О РИСКАХ (ОБЯЗАТЕЛЬНО К ПРОЧТЕНИЮ)

**Данная стратегия относится к классу HFT / Order Flow и предназначена для торговли НА РЕАЛЬНОМ СЧЁТУ.**

### Критические риски:

1. **Латентность исполнения**: Стратегия требует сверхнизкого пинга. Без колокации реальная задержка может быть выше требуемой, что приводит к проскальзываниям и ложным срабатываниям.

2. **Спуфинг и айсберги**: Крупная лимитная плотность в стакане может быть:
   - **Спуфингом** (снимается до исполнения) → ложный сигнал
   - **Айсбергом** (реальный объём больше видимого) → неполная информация

3. **Cumulative Delta приблизительна**: Классификация сделки как покупка/продажа делается по агрессору сделки — это оценка потока, а не истинный Order Flow с матчинга биржи.

4. **Риск потери капитала**: HFT-стратегии могут генерировать значительные убытки при неправильной настройке или неблагоприятных рыночных условиях.

### Обязательные меры безопасности:

- ✅ **Первый запуск**: ТОЛЬКО с минимальным риском на сделку (`risk_per_trade_pct=0.01`)
- ✅ **Консервативная конфигурация**: Минимальный объём позиции, жёсткий дневной лимит убытка
- ✅ **Kill-Switch включён**: `riskManagementEnabled=true`
- ✅ **Серверные стопы**: `serverStopEnabled=true` для защиты от падения модуля
- ✅ **Мониторинг**: Постоянный контроль за логами и метриками в первые часы работы

### 3. Мониторинг работы

#### Логи:
```bash
# Следить за логами в реальном времени
tail -f logs/orderbook.log | grep -E "(OPEN|CLOSE|WARN|ERROR|EMERGENCY)"
```

#### Метрики:
- `analytics/orderbook-metrics.csv` - CSV с метриками всех сделок
- `analytics/orderbook-diagnostics-replay.log` - детальные диагностические логи

#### Ключевые метрики для контроля:
- **Entry Quality Score** - качество входа (должен быть > 0.30)
- **Net PnL** - чистый PnL после комиссий
- **Hold Time** - время удержания позиции
- **Skip Reasons** - причины пропуска сделок

## 🔧 Аварийная остановка

### Ручной аварийный стоп (TODO.md Section 5)

Если вы видите критические проблемы (неисполнение стопов, рассинхрон стакана):

```java
// Вызвать через JMX или API
orderBookTradingEngine.requestManualEmergencyStop();
```

**Что происходит:**
1. Все открытые позиции закрываются по рынку НЕМЕДЛЕННО
2. Торговля останавливается
3. Отправляется уведомление в Telegram

### Автоматические защитные механизмы

| Механизм | Триггер | Действие |
|----------|---------|----------|
| **Kill-Switch** | daily_max_loss_pct достигнут | Остановка до конца дня |
| **Stream Outage** | Нет данных > 60 сек | Закрытие позиций |
| **Server SL** | Падение модуля | Закрытие на стороне биржи |
| **Manual Stop** | Внешний вызов | Немедленное закрытие |

## 📊 Диагностика проблем

### Частые проблемы и решения

#### 1. "trade_flow_too_weak"
**Проблема**: Недостаточный объём сделок для входа
**Решение**: Увеличить `minTradeFlow` или выбрать более ликвидные инструменты

#### 2. "entry_quality_below_threshold"
**Проблема**: Качество сигнала ниже порога
**Решение**: Проверить `ENTRY_QUALITY_THRESHOLD` (по умолчанию 0.30)

#### 3. "spread_widen"
**Проблема**: Спред расширился выше допустимого
**Решение**: Увеличить `maxSpreadBps` или избегать торговли в низкую ликвидность

#### 4. "reconciliation_mismatch"
**Проблема**: Расхождение с позицией на бирже
**Решение**: НЕМЕДЛЕННО остановить стратегию и проверить логи
